## CISA_KEV_COVERAGE.md

# CISA Linux KEV Coverage Notes

This repo does **not** attempt to detect CVE IDs directly. Instead, it watches for exploitation **behaviors** that are common across many Linux privilege-escalation and container-escape vulnerabilities.

That matters for the CVEs listed in `CISA-KVE-linux.md`, because many of them are kernel exploit families where the practical detection surface is:
- exploit helper execution
- namespace abuse
- overlayfs / mount abuse
- access to kernel-sensitive files
- post-exploitation persistence steps

## What was added

### Falco
Local rules in `falco_rules.local.yaml` now add:

- a crashpad ptrace allowlist to reduce desktop false positives
- a targeted desktop auth-helper exception for `/etc/shadow` and `/etc/pam.d/*`
- a rule for **unprivileged namespace or overlayfs exploit tooling**
- a rule for **suspicious reads of kernel exploit-sensitive files**
- a rule for **suspicious writes of kernel exploit-sensitive files**

### osquery
Scheduled queries in `osqueryd.conf` and `osqueryd-ssd-optimized.conf` now add:

- `kev_namespace_tooling`
- `kev_sensitive_mounts`
- `kev_sensitive_kernel_file_access`

## Behavior families now covered better

### 1. Namespace / overlayfs / idmap exploitation
These detections are intended to improve visibility into exploit chains that rely on helpers such as:
- `unshare`
- `newuidmap`
- `newgidmap`
- `nsenter`
- `fuse-overlayfs`
- overlay-related mount activity

This helps for the class of Linux KEV items that rely on user namespaces, overlayfs, id-mapped mounts, or related privilege-boundary mistakes.

### 2. Kernel-sensitive loader / tunable abuse
These detections watch access to files such as:
- `/etc/ld.so.preload`
- `/proc/sys/kernel/core_pattern`
- `/proc/sys/kernel/modprobe`
- `/proc/kallsyms`
- `/proc/kcore`
- `/etc/modprobe.d/*`

This helps catch exploitation and post-exploitation patterns that use kernel helper abuse, symbol discovery, loader hijacking, or persistence-oriented escalation chains.

### 3. Suspicious exploit-supporting mounts
The new osquery coverage improves visibility into mounts involving:
- `overlay`
- `fuse.overlayfs`
- `debugfs`
- `tracefs`
- `securityfs`
- `bpf`
- `/sys/kernel/debug`
- `/sys/fs/bpf`

This is useful for exploit staging, BPF-heavy abuse, and post-exploitation kernel introspection.

## Important limitations

- These are **behavioral detections**, not proof that a specific CVE was exploited.
- The current host still shows LinuxKit / eBPF tracepoint limitations for Falco, so syscall-level coverage is only partially validated here.
- osquery coverage is periodic, so it is best for snapshots and artifact discovery, not low-latency syscall tracing.

## Suggested usage

Use Falco for:
- near-real-time exploit-helper execution
- suspicious file access/write activity
- kernel-adjacent abuse that produces a syscall trail

Use osquery for:
- recurring snapshot checks
- exploit artifact discovery
- mount and process state review
- post-incident triage and baseline comparison
